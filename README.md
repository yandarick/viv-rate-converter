# 影核 · 智能核价演示系统

版本：2026.11.12。支持供应商报价与邮件日期整理、规则转换、已有价格比对、涨价确认、真实 Excel 模板下载，以及模拟内部系统查询和导入回执。

本项目是**规则解析与人工确认的演示系统**，未接入大模型、邮箱账号或真实 Viv 内部系统。供应商预置配置、初始编码、费率和下载示例均用于模拟；导入回执只说明当前模拟工作区已更新，不能作为真实业务验收。

- [系统指南](docs/system-guide.md)：结构、输入输出、实际规则、限制、部署备份与验证。
- [接口指南](docs/api.md)：会话、请求字段、响应、完整模拟流程与错误处理。

## 访问与五分钟演示

- 本地运行：建议使用与镜像一致的 Python 3.13，命令见下方；`python app.py` 默认监听 `http://127.0.0.1:18041`。
- 容器运行：执行 `docker compose up -d --build`，访问相同的本地地址。
- 本仓库对应2026-11-12演示版；现有说明记录首次发布为2026-11-16，本次未独立核验发布记录。部署示例已通用化，不含内部主机、真实客户报价、邮件或数据库。

在仓库根目录执行，Windows 可用 `py -3.13` 替换创建环境时的 `python`：

```sh
python -m venv .venv
```

激活环境：Windows PowerShell 用 `.\.venv\Scripts\Activate.ps1`；Linux/macOS 用 `. .venv/bin/activate`。随后执行：

```sh
python -m pip install -r requirements.txt
python app.py
```

打开上述本地地址。另开终端可用 `curl.exe http://127.0.0.1:18041/health`（Linux/macOS 用 `curl`）查看版本与 `system_mode: mock`。首次使用建议按以下步骤操作：

1. 打开页面，选择“短信双向示例”。页面载入纯模拟报价，并选择模拟 Standard SMS 规则。
2. 点击预览：8 条报价中有涨价、空日期、非数字 MNC、编码不在字典及前导零示例。基准、规则和处理来源可核对。
3. 核对并勾选规则、涨价确认；存在阻断行时，需处理或明确同意只导出可处理行。下载真实 BIFF8 `.xls`，涨价费率用黄色标注。
4. 点击“导入模拟系统”，把本次导出的文件实际上传校验，取得回执；下方模拟价格更新。再次预览同一报价时，已导入价格不再显示涨价。
5. 可加载示例邮件或粘贴邮件正文。选择识别出的生效日期后重新预览，空日期按明确选择补齐并转 GMT+8。多日期不自动猜。
6. 可切到“语音示例”，演示呼出、呼入、下载和模拟导入。语音五列是演示结构，尚无 Viv 正式导入模板，也未实现截图中的首次/分段计费周期业务。

## 供应商与字段适配

配置保存在本浏览器工作区，可以维护供应商、源时区、币种、价格除数、表头、异常策略与人工编码映射。网页允许维护模拟合法编码和基准价。

| 预置配置 | 说明 |
| --- | --- |
| 模拟 Skyline SMS | 预置表头 MCC/MNC、New Price (EUR/100)、Price Valid from；除数为 100 |
| 模拟 Standard SMS | New Price、MO、Effective Date；包含双向纯模拟示例 |
| 模拟语音供应商 | CC、MNC、Outbound、Inbound、Effective Date，币种 USD；仅演示模板 |
| 腾讯样表适配 | 预置 MCCMNC 映射含 730、5051 等来源标识，按国家级数据演示；使用显式模拟映射，不擅自拆成运营商编码；USD 为演示配置，真实币种和单位仍需核对 |
| 火山样表适配 | 选择“混合”工作表，按 MCC 的国家级报价处理；USD 来自表头，计费单位仍需确认；模拟字典未覆盖的国家明确阻断 |

编码输入可用 MCC/MNC 分列、5/6 位数字合并码，或人工维护的来源编码到 MCC/MNC 映射。国家级数据不能凭空生成真实运营商。多工作表文件须明确工作表名称，避免选错报价类型。

## 已实现的处理规则

- 使用配置的新价列，按 MT/MO 或呼出/呼入提取。表头币种与配置冲突时报错；明确每100单位的表头须配置除数100，不做自动外汇换算。
- 双向模式未配置 MO 列或 MO 单元格为空时，上行默认0；已配置 MO 列但整列缺失时直接报错。仅下行模式也输出上行0，会在导入时覆盖原上行价，使用前须核对。仅上行文件保留目标编码已有下行价，无基准时阻断。
- 非空日期按供应商时区转 GMT+8。邮件只识别正文日期，不把邮件发送日期、文件名或腾讯表头的普通 Date 自动当作生效日。接受 `.eml`、UTF-8 `.txt` 或粘贴正文；不登录邮箱、不调用外部 AI 服务。
- 空日期可选择：邮件/手填后沿用模拟系统日期、只手填、同表唯一日期、排除。历史日期回填与同表唯一日期均是可见演示策略，不宣称已获真实业务批准。时区歧义会要求明确 UTC 时差。
- 编码以当前模拟字典为准；未知或非数字 MNC 按配置排除、取本供应商本文件同 MCC 各方向最高价，或取约定单价。MNC 999 是显式模拟替代值，真实值待业务确认。
- 默认约定价5 USD为演示配置，本次未核对真实合同。约定币种与报价币种不同时，必须填写明确换算系数，缺失则阻断；不会猜测汇率。
- 一致的重复结果合并；相同目标编码但报价或日期冲突时阻断。最高价不扩大为所有正常重复报价都取最高。
- 预览比对已有费率；涨价需明确确认，导入在事务中重新比价。输出文件绑定本浏览器、供应商、币种、业务及文件内容，证明1小时有效；更换文件或配置币种后需重导。

短信输出仍为 `Sheet1` 的五列：MCC、MNC、下行费率、上行费率、生效时间。语音演示输出为 CC、MNC、呼出费率、呼入费率、生效时间。

## 模拟接口

页面使用同源会话；脚本调用必须保留 Cookie，才能操作同一工作区。模拟 JSON 成功响应声明 `mode: mock`，文件响应使用二进制；健康检查使用 `system_mode: mock`，错误响应格式见[接口指南](docs/api.md)。每个签名工作区独立，接口不接收真实内部系统地址或凭据。签名 Cookie 不是登录认证，也不是外部访问控制。

| 接口 | 功能 |
| --- | --- |
| `GET/POST /api/suppliers` | 查询/保存供应商配置 |
| `GET/POST /api/mock/operators` | 查询/维护模拟合法编码 |
| `GET/POST /api/mock/rates` | 查询/维护模拟基准价格，写入须显式确认 |
| `POST /api/mock/query` | 批量查询，JSON 含 supplier_id 和 keys，例如 `["460:00"]` |
| `POST /api/workflow/preview` | 报价文件、邮件及规则解析，返回全部处理行、异常与涨价 |
| `POST /api/workflow/export` | 重算并导出xls，返回 `X-Export-Proof` |
| `POST /api/workflow/import` | 校验本次xls及证明，导入模拟库并返回回执 |
| `POST /api/mock/import` | 规范JSON接口模拟导入；严格校验币种、编码、日期与涨价 |
| `GET /api/mock/receipts` | 当前工作区回执 |
| `POST /api/mock/reset` | 重置当前工作区，不影响其他浏览器 |
| `GET /api/examples/sms_mt`、`sms_mo`、`sms_both`、`voice` | 动态生成纯模拟xls |
| `GET /api/examples/email.eml` | 纯模拟供应商邮件 |

原 `/api/analyze`、`/api/convert` 作为旧版兼容接口保留，不代表新增业务规则的入口。

## 数据与运行

原始 Excel 和邮件按请求处理，不作为业务文件持久保存，也不发送给外部 AI。本地运行的大文件可能使用系统临时文件；所附容器配置将临时目录放在内存中。用户明确导入的标准报价、供应商规则、合法编码、基准价及回执保存在隔离模拟库，闲置30天清理；清理浏览器Cookie后无法找回原工作区。

数据库和签名密钥位于 `VIV_DATA_DIR`，部署为 `/data` 命名卷；根目录只读，进程为非root，临时目录为内存。真实供应商原件不打包到镜像，演示下载仅含合成数据。

限制：请求10MB、报价20000行、64列、20张工作表；JSON最多8MB；每区50供应商、20000编码、50000报价、200回执，最多200工作区。解析还限制共享字符串、实际单元格坐标与解压体积。附带的nginx示例限制接口每来源IP每分钟60次，可短时突发20次。

## 本地、检查与部署

安装 `requirements.txt`。本地执行 `python app.py`，默认启动 `127.0.0.1:18041`；默认数据目录 `.runtime`，可用 `VIV_DATA_DIR` 改为专用目录。

```sh
python -m unittest discover -s tests -v
node --check static/app.js
python tests/verify_system.py --base http://127.0.0.1:18041 --output .agent/tmp/verify-output --state .agent/tmp/verify-state/session.json
```

HTTP验收另需 `pip install requests`；浏览器检查需安装Playwright与Chrome，不作为运行服务依赖。浏览器验证执行 `node tests/browser_workflow.mjs`，可用 `VIV_BASE_URL` 指定自己部署的地址。

**历史验证记录：63项，62项通过、1项跳过；本次文档更新未重新运行该测试套件。** 当前实际数量和结果以执行输出为准。跳过项依赖私有原件；如已有合法取得的原件，可用环境变量 `VIV_PRIVATE_SOURCE` 和 `VIV_PRIVATE_TEMPLATE` 指定两个文件路径，仓库不提供原件。其他测试与页面示例使用合成数据。测试会初始化模拟存储，运行前应将 `VIV_DATA_DIR` 指向独立测试目录，勿指向需要保留的演示数据。

```sh
docker compose up -d --build
docker compose ps
```

Compose默认只监听127.0.0.1。需要互联网访问时，在自己的可信网关配置TLS、请求大小和频率限制；`deploy/nginx.conf.example` 中的example.com及证书路径需替换。若nginx在容器中运行，须按自己的网络设置上游地址。

演示系统没有账号登录；签名Cookie隔离工作区，不代替用户认证。只用于有限人员演示，正式生产需另外设计访问控制和业务审批。

备份须同时保存数据库和会话签名密钥，具体停机备份、恢复条件见[系统指南](docs/system-guide.md)。重启会保留模拟数据，勿以删除卷方式升级。`VIV_SECURE_COOKIE=1` 使服务信任一层代理的 `X-Forwarded-Proto`；网关必须覆盖该头。Cookie 是否标记 Secure 由识别出的请求协议决定，直接本地 HTTP 仍可维持工作区。

此版本完成可独立运行的演示流程。真实系统API契约、编码库、最终日期策略、腾讯真实币种/计费单位和语音正式模板仍需业务确认，不能把模拟导入回执解释为真实系统上线验收。
